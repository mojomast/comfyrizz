# `@comfyrizz/renderer` — Remotion CPU renderer

Owner: **Pi** (WS-A). Spec §6.3, §6.9; PLAN A1/A3/A5.

Remotion is pinned to **4.0.536**. The project is driven by the two committed
files in the bundled example:

- `examples/launch-demo/package.json` — `comfyrizz.package/v1` (validated with
  `packages/schema/bin/comfyrizz-validate.mjs`)
- `examples/launch-demo/timeline.json` — compiled by `packages/planner` (A2);
  the renderer never re-derives frame positions

`src/generated-assets.ts` is generated by `scripts/build-assets.mjs`: every
`llm-svg` asset is sanitized and rasterised with `@resvg/resvg-js` before it is
inlined, so the composition only ever sees verified markup.

## Layouts

`Title` (centered/outro), `Hero` (split/full-bleed), `Stat`, `Chart` (SVG bars,
zero baseline), `List` (bullets/quote). Registered compositions:

- `LaunchDemo` — full example, 1095 frames @ 30 fps (36.5 s), 1920×1080
- `PackageDemo` — the same component with `calculateMetadata`, so a render can
  swap in any `(package, timeline)` props (used for `examples/showcase-gpu2`).
  It plays the package's measured narration audio and burns in measured
  captions when the timeline has them (N7), so `renderPackage` on a narrated
  package exports the narrated length instead of `preferredFrames`.
- `NarratedDemo` — Kokoro audio + sentence-caption overlay, 1312 frames @ 30 fps (43.7 s) (A4)
- `Preview-Title`, `Preview-Hero`, `Preview-Stat`, `Preview-Chart`, `Preview-List`
  — one scene each, for frame 0 / mid / last stills

## Media layer (P-fix1)

Raster/video assets can fill the frame or sit in a framed panel:

- `background.asset` (+ `fit`/`loop`/`muted`/`speed`/`trim`) renders an
  `Img`/`OffthreadVideo` fill; short clips are stretched (down to half speed)
  before looping. A dark `background.scrim` (0..1) is drawn between the media and
  the layout text.
- `foreground[]` with an `image`/`video` asset renders a rounded `MediaPanel`
  (x/y/w/h/z + `anim`: `slide-in`, `fade-in`, `zoom-in`, `ken-burns`,
  `parallax-in`, `none`).
- `scene.media_only` (or a sidecar `skipLayout`) skips the layout and draws the
  media + scrim + panels + `scene.lower_third` (`{ kicker?, text }`). Both fields
  are carried through `compileTimeline` into `timeline.json` (P-fix3 N8), so a
  render from the timeline keeps them.
- `theme.text` / `theme.text_muted` / `theme.text_on_accent` decouple text from
  `palette[0]` (which may be `transparent`); defaults stay identical for the
  existing 4-colour packages.

The field names are Hermes's H-fix1 (`packages/schema`). `compileTimeline`
carries `media_only`/`lower_third` into the timeline (N8); the renderer still
accepts an `examples/<name>/media.json` sidecar (`scrim`, `skipLayout`,
`lowerThird`) for older timelines, and the scene fields win when both are
present. The resolution logic lives in `src/media-model.js` and is unit-tested
on plain Node 20 (`npm test`, no type stripper).

## Determinism

Each frame is a pure function of `(package, timeline, local frame)`. There is no
CSS time animation, no `Date.now()`, no `fetch`, no LLM and no network at render
time; the only external file is the pinned local Inter font
(`public/fonts/Inter-Variable.ttf`, OFL-1.1, license alongside).
Fonts are loaded with `@remotion/fonts` `loadFont`, which blocks the render with
`delayRender` until the FontFace is ready.

Copy that exceeds the schema's readability limits is a **visible red fail
state** (`CopyGuard`), never silent clipping.

## Video component decision

Media backgrounds and panels use `<OffthreadVideo>` (the stable looping-capable
component in the pinned 4.0.536 build). The CPU slice has no video assets, so
`LaunchDemo`/`NarratedDemo` remain procedural; `examples/showcase-gpu2` exercises
the media layer end to end. `@remotion/transitions` fades are used for the
compiled transitions.

## Commands

```bash
npm install                     # local to apps/renderer; no lockfile committed
npm test                        # schema/timeline/asset/network/media/layout/incremental checks
npm run build:assets            # sanitize + render-check the 4 SVG assets
npm run compile:example -- --example examples/data-story   # package.json -> timeline.json (A2 compiler)
npm run recompile:timeline -- --example examples/showcase-gpu2  # recompile a committed timeline (P-fix3)
npm run recompile:timeline -- --all                            # recompile every bundled example
npm run still                   # 15 stills (5 layouts x frame 0/mid/last)
npm run still:example -- --example examples/data-story     # one midpoint still per scene
npm run render:example          # CPU MP4 + ffprobe gate (silent example)
npm run render:package -- --example examples/data-story    # incremental per-scene export (A6)
npm run render:showcase         # examples/showcase-gpu2 via PackageDemo (P-fix1)
npm run render:narrated         # Kokoro audio + captions, ffprobe audio gate (A4)
npm run layout:check            # text/asset overlap unit tests (A6)
```

`render:example` and `still` use `/usr/bin/google-chrome` by default; override
with `REMOTION_BROWSER=/path/to/chrome`.

## Timeline freshness (P-fix3)

A committed `examples/*/timeline.json` must equal a fresh compile of its
`package.json` (with the measured chunks in `audio/durations.json` when the
example is narrated). `test/timeline-freshness.test.mjs` enforces this for every
bundled example and names the stale one. When an example does not commit
`audio/durations.json` (so a clean clone cannot recompile with measured
narration), the guard falls back to checking the committed timeline against its
`narration-report.json` frame counts and reports the weaker mode as a
diagnostic; measured examples are always compared exactly. Narration metadata
(`audio/durations.json`, `audio/loudness.json`) is committed by every narrated
example. Recompile a stale timeline without re-synthesizing audio:

```bash
npm run recompile:timeline -- --example examples/showcase-gpu2
npm run recompile:timeline -- --all
```

`render:narrated` and `packages/tts/scripts/narrate.mjs` write the timeline with
measured narration; this script is the offline equivalent and also refreshes
`narration-report.json`'s `timelineHash`.

## Bundled examples

Two silent examples exercise every layout and the incremental CPU export:

- `examples/product-explainer` — product explainer, 1349 frames @ 30 fps
  (44.97 s), layouts `title, hero, hero, stat, chart, list, title`, one narrated
  scene set (Kokoro), captions in `captions.srt`/`captions.vtt`.
- `examples/data-story` — data story, 1320 frames @ 30 fps (44.00 s), layouts
  `title, hero, chart, stat, hero, list, title`.

Both use mostly `llm-svg` assets (including one `vector-anim` part each) and
reference FLUX/LTX assets only as `pending` foregrounds with procedural
fallbacks, so the export path never calls an LLM, a GPU or the network.

Two GPU-media showcases carry real FLUX/LTX/SVG-guide media from the GPU test
sessions plus measured Kokoro narration:

- `examples/showcase-gpu2` — GPU test 2 solar explainer, 1312 frames @ 30 fps
  (43.733 s), layouts `title, hero, hero, stat, hero, chart, title`, scrims and a
  `media.json` lower-third sidecar, captions committed.
- `examples/showcase-gpu3` (A7) — GPU test 3 wind explainer, 1092 frames @ 30 fps
  (36.400 s), layouts `title, hero, hero, stat, hero, title`, five LTX plates
  retimed 24→30 fps by the compiler, `media_only`/`lower_third` via `media.json`,
  captions committed.

Their `assets/*.mp4`, `assets/*.png`, `audio/*.wav` and `out/` media stay out of
Git (`.gitignore`) and come from the GPU test session; the committed
`package.json`, recompiled `timeline.json` and `narration-report.json` are the
source of truth and are checked by the freshness guard above.

### Media in a clean clone (P-fix4)

The GPU showcases are reproducible from the committed manifests alone. When a
declared media file is not in the clone (the usual case for a fresh checkout),
`renderPackage`/`renderPackageIncremental` list it with `missingMediaFiles()`
and pass the file list to the composition as `missingMedia`. The renderer then:

- draws a labelled **`media not in this clone`** placeholder (palette gradient +
  the asset id, generator and workflow) wherever the background or a foreground
  panel would have used the file, instead of asking Remotion for a 404;
- renders **silent** with the **committed captions** when the narration file is
  absent (`SafeAudio` drops missing audio instead of crashing Studio);
- logs **one warning per missing asset** and never crashes.

`npm run still`, `render:package` and the incremental export all share this
path, so opening a clean clone in Remotion Studio or exporting it works with no
network and no GPU. Re-running the export after the media is present picks up
the real files automatically.

`node scripts/clean-clone-check.mjs` verifies this end to end: it makes a
throwaway `git worktree` of `HEAD`, links the main tree's `node_modules` (the
repo has no `pnpm-lock.yaml`), builds `packages/planner` + `packages/vector`,
runs the renderer + planner suites, exports `examples/launch-demo` and asserts
the ffprobe frame count equals the committed timeline, then removes the
worktree.

`render:package` renders each scene as its own content-addressed segment under
`apps/renderer/.cache/<pkg.id>/`, so an unchanged scene is reused and a one-scene
edit only re-renders the affected segment (plus the fade before it).

| Example | Frames | Duration | CPU render | Reuse probe |
|---|---|---|---|---|
| `examples/data-story` | 1320 | 44.000 s | **125.5 s** (7 rendered, 0 reused) | `rendered 0, reused 7` |
| `examples/product-explainer` | 1349 | 44.967 s | **124.9 s** (7 rendered, 0 reused), H.264 + AAC | `rendered 0, reused 7` |
| `examples/showcase-gpu3` | 1092 | 36.400 s | **132.7 s** (6 rendered, 0 reused), H.264 + AAC | `rendered 0, reused 6` |

Render times are CPU-only, `--concurrency=2`, `/usr/bin/google-chrome`, Node
20.19.2. `render:package` hard-fails before rendering if any foreground asset
would overlap body copy or a caption (`findLayoutOverlaps`).
